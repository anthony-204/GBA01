# Fuse Tool — Data Report

**Last updated:** June 2026  
**Applies to:** All branches (`main`, `client/v0`, `client/v1`, `client/v2`) — they share the same JSON under `fuse-tool/data/`.

This report documents every dataset used by the GBA Fuse Tool: where it came from (the original Excel application), what it contains, how complete it is, how it is loaded at runtime, and known quality gaps.

---

## Executive summary

| Item | Value |
|------|-------|
| **Original source** | `Fuse_GUI_APP.xlsx` (legacy Excel GUI) |
| **Expected path** | `Resources/Tool/APP_Fuse/Fuse_GUI_APP.xlsx` (relative to repo root) |
| **Import script** | `fuse-tool/scripts/import_from_xlsx.py` → `npm run import:data` |

### Import conventions

- **MachinesOnSite:** Row 2 = headers; data from row 4. Vehicle `id` = column D (**Model**).
- **Headers:** Normalized to camelCase JSON keys; known Excel typos corrected (e.g. `Manufcturer` → `manufacturer`).
- **Sentinel values** cleared at import: empty, `TBC`, `Select`, `N/A`, `#N/A`, `data unavailable`.
- **Excel errors** (e.g. `#VALUE!`) are preserved as strings and treated as missing at calculation time (`parseNumber` → `null`).

## 3. Dataset schemas and usage

### 3.1 `constants.json`

Global defaults used by the full V2 engine (`calculate.ts` on `main`):

| Field | Value | Meaning |
|-------|-------|---------|
| `defaultSafetyFactorPercent` | 25 | Default fuse sizing margin |
| `defaultPeakCrankingLimitA` | 1000 | Fallback when machine cutoff missing |
| `minCrankingTimeRequiredS` / `maxAdiabaticCrankingTimeS` | 5 | Cranking / thermal time window |
| `defaultKFactorCopper` | 143 | Fallback K (XLPE 90°C) — **not used** in GBA-0002 strict K lookup |
| `defaultElectricalSystemV` | 24 | Nominal system voltage |
| `minBatteryVoltage24V` | 16.48 | Fleet battery floor (main tool) |
| `voltageDropPercentLimit` | 3 | Max allowable % drop (main tool) |
| `standards` | AS/NZS 5000.1, 1125, 1995:2003 | Reference standards |

### 3.2 `machines.json` — fleet records

Each record is one vehicle on site. Core typed fields (`packages/engine/src/types.ts`):

| Field | Excel / meaning | Used by |
|-------|-----------------|---------|
| `id` | Model (column D) | Lookup key |
| `sourceRow` | Excel row number | Traceability |
| `site`, `manufacturer`, `model`, `category` | Identity | UI display |
| `electricalSystemV` | System voltage (V) | Checks |
| `minBatteryVoltageV` | Minimum battery (V) | Main tool battery check |
| `peakCurrentCutoffA` | Starter peak limit from power & efficiency | Cranking limit check |
| `peakCrankingCurrentA` | Peak continuous cranking current (A) | GBA-0002 required |
| `inrushCurrentA` | Measured inrush | Reference |
| `crankingTimeMeasuredS` / `crankingTimeRequiredS` | Cranking duration | Thermal / time checks |
| `crankingVoltageMeasuredV` | Measured cranking voltage | Reference |
| `alternatorContinuousA` | Alternator continuous (A) | Fuse sizing, cable continuous |
| `cableType` | Cable type label (column AD) | **K-factor lookup** (GBA-0002) |
| `cableSizeMm2` | Conductor size | Resistance, thermal |
| `cableContinuousA` | Site continuous rating | May exceed `cable-capacity.json` table |
| `cableLengthM` | Run length | Voltage drop (main tool) |
| `operatingTempC` | Operating temperature | Temperature check |
| `fuseInstalledA` | Installed fuse (A) | Comparison / display |

**Additional imported fields** (examples): `engine`, `batteryConfiguration`, `starterMotorType`, `alternatorType`, `cablePeakA`, `efficiencyPercent`, `powerAtCutoffKw`, `link`, etc.

#### Fleet cable types in use

Site machines reference cable types **not** in `cable-capacity.json`:

- `OEM Wiring`, `Weldflex`, `weldflex`, `Narva`

For these, **K-factor** comes from `copper-k-factors.json` (matched by label), and **continuous current** comes from the machine record itself.

#### Cable sizes in fleet data

Only **70, 95, and 120 mm²** appear on complete vehicles. Resistance for voltage-drop and some GBA paths is resolved from `cable-capacity.json` by size (nearest table row).

#### Sites

- **35** vehicles: `SEE Civil Pad, Tailings Dam, Cadia`
- **2** vehicles: `Newmont` (`637G`, `D6/D6 XE`)

### 3.3 `fuse-library.json`

Little Fuse **MEGA 32V** range; GB part holder **GB161280**.

| Field | Description |
|-------|-------------|
| `ratingOptionA` | Standard fuse rating (A) — primary lookup key |
| `gbPartHolder` | GB Engineering part holder code |
| `manufacturer`, `description`, `manufacturerPartNumber` | Part identity |
| `currentRatingA` | Manufacturer rated current |
| `i2tA2s` | I²t for adiabatic time derivation |
| `breakingCurrentA` | Breaking current for I²t row |
| `timeFromI2tS`, `timeFromGraphS` | Withstand times (s) |
| `interruptingRating`, `temperatureRangeC` | Datasheet limits |
| `link` | Datasheet URL |

**Valid ratings (rows 1–7):** 125, 150, 175, 200, 225, 250, 275 A.

**Corrupt rows (8–9):** Mis-parsed Excel cells — `ratingOptionA` values **285** and **0.43** with numeric garbage in text fields. These can pollute fuse rating sort lists on `main` until filtered or the source sheet is fixed and re-imported.

### 3.4 `mega32v-curve.json`

Time–current withstand matrix for fuse ratings **300–500 A** at discrete cranking currents:

| Cranking current (A) | 500 | 600 | 650 | 700 | 800 | 900 | 1000 | 1200 |
|----------------------|-----|-----|-----|-----|-----|-----|------|------|
| Rows in file | Full | Full | **Sparse** (300 A only) | Full | Full | Full | Full | Full |

Used with `fuse-library.json` for fuse withstand checks. Sparse rows fall back to `timeFromGraphS` from the library when a direct matrix lookup is unavailable.

### 3.5 `cable-capacity.json`

AS/NZS-style **Two Single Core** XLPE table:

| Insulation | kFactor | Sizes (mm²) | maxConductorTempC |
|------------|---------|-------------|-------------------|
| X-90 XLPE | 143 | 50, 70, 95, 120 | 90°C |
| X-110 XLPE | 150 | 50, 70, 95, 120 | 110°C |

Each row includes `continuousCurrentA` and `resistanceOhmPerKm`.

**Scope limit:** This table does not cover OEM/Weldflex/Narva site cables; those use machine-stored `cableContinuousA` (often higher than the table — e.g. 70 mm² → 314 A on a machine vs 274 A in the table).

### 3.6 `copper-k-factors.json`

Adiabatic copper K values for thermal withstand \((k \times S / I)^2 \geq t\).

**Usable rows (11):**

| `cableTypeLabel` | `kCopper` |
|------------------|-----------|
| Thermoplastic 70°C (PVC) | 115 |
| Thermoplastic 90°C (PVC) | 100 |
| Thermosetting 90°C XLPE EDR | 143 |
| Thermosetting 60°C rubber | 141 |
| Thermosetting 85°C rubber | 134 |
| Thermosetting 185°C silicone rubber | 132 |
| Thermosetting 110°C XLPE | 150 |
| OEM Wiring | 143 |
| Weldflex | 150 |
| Weldflex PVC | 115 |
| Narva | 150 |

**19 additional rows** are section headers / documentation (`kCopper: null`) from the Excel sheet layout.

**GBA-0002 rule:** `lookupKFactorStrict()` matches `machines.cableType` to `cableTypeLabel` — **no default K**. Unknown type → `ENGINEERING REVIEW REQUIRED`.

## 4. Fleet completeness

### 4.1 V2 completeness gate

Defined in `packages/engine/src/completeness.ts`. A vehicle is **complete** when all of the following parse as valid numbers (or non-empty string for `cableType`), **plus** a cranking time:

| Required field | Extra rule |
|----------------|------------|
| `peakCrankingCurrentA` | > 0 |
| `alternatorContinuousA` | > 0 |
| `cableType` | non-empty string |
| `cableSizeMm2` | > 0 |
| `cableContinuousA` | > 0 |
| `cableLengthM` | ≥ 0 |
| `operatingTempC` | valid |
| `peakCurrentCutoffA` | **> 0** (strings like `#VALUE!` fail) |
| `electricalSystemV` | > 0 |
| Cranking time | `crankingTimeMeasuredS` or `crankingTimeRequiredS` |

### 4.5 Why exactly these nine are hardcoded in v0 (not eleven)

The v0 dropdown is **not** generated from “all machines with enough data for `calculateGba0002`”. It is a **fixed allow-list** in `packages/engine/src/gba0002/constants.ts` (`GBA0002_CLIENT_MACHINE_IDS`). That list was set when the GBA-0002 **client deliverable** branch was first built, for two independent reasons:

| Reason | Detail |
|--------|--------|
| **1. Client scope** | The client confirmed a **nine-machine sample** for the prototype (GBA-0002 PDF “Machine sample list” — only **D10T** is named; slots 2–9 are blank). The deliverable was scoped to **9**, not “all calculable rows”. |
| **2. V2 completeness audit** | At branch creation, the nine IDs were taken from machines that pass **`assessVehicleCompleteness()`** on `main` — the **full engineering gate** requiring **Q** (`peakCurrentCutoffA` > 0), **T**, alternator, cable block, `electricalSystemV`, cranking time, etc. Exactly **nine** of 37 rows pass; those nine became the hardcoded list. |

**Important distinction — this is not the same as the v0 calculation gate:**

| Gate | What it checks | Count | Includes 120T / 69T? |
|------|----------------|-------|----------------------|
| **V2 complete** (used to **pick** the 9) | T + **Q** + full cable + system V + … | **9** | **No** — 120T has Q = `#VALUE!`; 69T has Q = 0 |
| **GBA v0 calculable** (what the **engine** needs) | T + alternator + cable type/size + K/R lookups | **11** | **Yes** — both have column T and cable data |
| **Hardcoded UI list** | Membership in `GBA0002_CLIENT_MACHINE_IDS` | **9** | **No** — unless IDs are added to the array |

So: **v0 already uses column T for math**, but the **nine-machine list was frozen using the stricter V2/Q completeness rule and client “9 machines” scope** — not by re-scanning “who is GBA-calculable on T alone”. That is why **120T** and **69T** are viable for v0 calculations but absent from the dropdown.

**16 V is not the reason.** The minimum starter voltage (16 V) is a **global constant** in v0 (`GBA0002_MIN_STARTER_VOLTAGE_V`) applied to every machine in the voltage-drop formula. It does not filter which machines appear in the list. Per-machine column N (cutoff voltage) is not read by v0.

**Were eleven machines ever “complete” in the same sense?** No — only **nine** are V2-complete. **Eleven** have sufficient data for **GBA v0’s lighter requirements** (T-path). The two extra machines are **near-complete** on V2: they fail only on **Q** (and 120T also lacks `electricalSystemV` in the sheet).

To expose 120T and 69T in v0: add their IDs to `GBA0002_CLIENT_MACHINE_IDS`, update tests/docs, and obtain client confirmation to expand beyond the original nine-machine scope (see `GBA0002_SPEC_CLARIFICATION_MEMO.md` §2).

### 4.4 GBA-0002 client requirements (subset of completeness)

`calculateGba0002()` requires per machine:

- Membership in `GBA0002_CLIENT_MACHINE_IDS`
- `peakCrankingCurrentA`, `alternatorContinuousA`, `cableSizeMm2`, `cableType`
- Resolvable K-factor and cable resistance
- User inputs: safety factor (25 or 50%), battery voltage during cranking

Does **not** require `cableLengthM` or `peakCurrentCutoffA` for the simplified client path (voltage budget uses fixed 16 V starter floor instead of fleet `minBatteryVoltage24V`).

## 6. Data quality issues and risks

| # | Issue | Impact | Mitigation |
|---|-------|--------|------------|
| 1 | Excel source not in repo | Cannot re-import without `Fuse_GUI_APP.xlsx` | Keep JSON under version control; document path |
| 2 | 21× `#VALUE!` on peak cutoff | 28/37 vehicles incomplete on `main` | Fix Excel formulas; re-run `import:data` |
| 3 | Fuse library rows 8–9 corrupt | Spurious fuse ratings (285 A, 0.43 A) | Fix Fuse_Library sheet; filter on import |
| 4 | `mega32v-curve` sparse at 650 A | Incomplete matrix lookup | Use `timeFromGraphS` fallback; complete sheet |
| 5 | `copper-k-factors` mixed with headers | 19 null-K rows | Import filter or ignore at lookup |
| 6 | Site vs table cable ratings | Machine `cableContinuousA` may exceed table | By design — site data overrides table for continuous check |
| 7 | Unimported Excel libraries | No starter/alternator library lookup | Enrich from MachinesOnSite only |
| 8 | `MD6250` stub | Project sheet not fully migrated | Complete MD6250 Project import |
| 9 | Case variant `weldflex` vs `Weldflex` | K lookup must match label exactly | Normalize on import or alias in lookup |
| 10 | 16 V vs 16.48 V min battery | Different results main vs GBA-0002 | Documented intentional branch split |

### Parsing sentinels (`parseValue.ts`)

Treated as unavailable: `TBC`, `N/A`, `#N/A`, `Select`, empty.  
`#VALUE!` is not explicitly listed but `Number("#VALUE!")` → `NaN` → treated as null.

### Fuse installed field quirks

Some machines store text instead of amperage: `"No Fuse installed"`, `"No Fuse instlled"` (typo in source).

## 10. Recommendations

1. **Restore or archive** `Fuse_GUI_APP.xlsx` in a known location (or document external storage) so imports are reproducible.
2. **Fix Excel formulas** for `peakCurrentCutoffA` on the 21 `#VALUE!` rows to unlock more fleet vehicles on `main`.
3. **Clean Fuse_Library** rows 8–9 in Excel before next import.
4. **Normalize** `weldflex` → `Weldflex` during import to avoid K-factor misses.
5. **Filter** `copper-k-factors.json` import to rows with non-null `kCopper`.
6. **Complete** `MD6250` migration from the MD6250 Project sheet if that vehicle is in scope.
7. **Consider importing** StarterMotors and Alternators24V libraries if manual column data is insufficient for new machines.
